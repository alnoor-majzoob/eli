# دليل مستخدم EIL — العربية

دليل شامل لمنصة **EIL** (طبقة الذكاء التنفيذية للمؤسسات: Enterprise
Execution Intelligence Layer): الصفحات، نموذج البيانات، الأدوار، وكيفية
استخدام كل ميزة.

---

## 1. المقدمة

EIL هي طبقة ذكاء تنفيذي للمؤسسات تضع الذكاء الاصطناعي في أعلى أنظمة السجلات
المصدر، مع:

- **النتائج الاستراتيجية**: الأهداف، النتائج الرئيسية، الفوائد، الالتزامات
  والمشاريع (الرسم البياني للعمل).
- **الطلبات إلى التسليم**: تقديم الطلبات → لوحة الأولويات → تحويل تلقائي
  للبرامج/المشاريع.
- **الترتيب (Prioritisation)**: محرك تسجيل يُشرح بوضوح، مع تجاوزات (SoD-2)
  وتدفق تسجيل بمساعدة الذكاء الاصطناعي.
- **القدرة والسيناريوهات (Scenario 3)**: تخصيص الموارد، خريطة الحرارة، تحليل
  تأثير الازدحام، ومُحسّن CP-SAT.
- **المخاطر التنبؤية (Scenario 4)**: ثقة التسليم عبر مونتي كارلو، نماذج
  التأخير، ومحرك التصعيد.
- **الرؤية التنفيذية (Scenario 5)**: الرؤية التنفيذية ستة أقسام في شاشة واحدة،
  بما في ذلك تجميع الفوائد.
- **الذكاء الاصطناعي**: "اسأل EIL" (بالعد اللاحق) وصندوق الذكاء الاصطناعي
  (AI Inbox).
- **حلقة تغذية راجعة للذكاء الاصطناعي**: استخراج أعمال التنفيذ من
  النصوص الصوتية لاجتماعات ورسائل البريد الإلكتروني (Scenario 1).
- **مركز التكامل**: سجل الموزع، المصادر الموافق عليها، المزامنة، النزاعات
  والكتابات الموجهة.

## 2. البدء

### 2.1 متطلبات النظام

- متصفح: Chrome، Edge، Firefox أو Safari الحديث.
- الواجهة البرمجية (API): لا شيء مطلوب — يتم تقديمها بواسطة الخادم
  نفسه.
- للحصول على المكدس الكامل (Docker/PostgreSQL/Redis/Keycloak) — راجع
  `infra/compose/docker-compose.yml`؛ غير متاح في هذا البيئة، لذلك
  يُستخدم الحل البديل المحلي (SQLite).

### 2.2 تشغيل المنصة

| الأمر | الإجراء |
|---|---|
| `make setup` | تثبيت تبعيات Python و Node (uv + pnpm). |
| `make migrate` | تطبيق ترحيلات قاعدة البيانات (SQLite المحلي في `.data/eil.db`). |
| `make dev` | تشغيل الخادم (API http://localhost:8000، Swagger `/docs`) والتطبيق (http://localhost:5173). |
| `make demo` | عرض عملي محلي حتمي (وضع الإعادة — `AI_ENABLED=false`). |
| `make up` / `make down` | المكدس الكامل عبر Docker Compose (يتطلب Docker). |
| `make seed-demo` | تعبئة بيانات عرض تجريبية إلى `.data/eil.db`. |
| `make check` | بوابة CI: الفحوصات + النوع الثابت + الاختبارات. |
| `make security-scan` | مسح الأنماط السرية + مراجعة التبعيات (§7). |

في حالة **عملية عرض جديدة**: `make setup && make migrate && make dev` — ثم
افتح http://localhost:5173.

ملاحظات:
- الوضع المحلي يستخدم SQLite + تسجيل دخول JWT للتطوير. في الإنتاج،
  `AUTH_MODE=oidc` وتسجيل الدخول عبر مزوّد الهوية
  (Keycloak/Entra ID).
- `make dev` يبدأ الخادم API مع إعادة تحميل آلي؛ يُطبّق الترحيلات عند
  البدء.
- `docs/` — مصفوفة القدرات (`docs/capability-matrix.md`)، معايير
  المقاييس التنفيذية (`docs/metrics.md`)، أداة تتبّع التقدم
  (`docs/PROGRESS.md`).

### 2.3 تسجيل الدخول

- **الوضع المحلي/التطوير** (`make dev`, `make demo`): صفحة تسجيل الدخول
  (http://localhost:5173/login) مع محدد الأدوار. اختر دورًا واضغط **Sign in**.
  على الواجهة البرمجية يمكنك أيضًا إصدار الرموز مباشرة:

  ```
  POST http://localhost:8000/api/v1/auth/dev-login
  Content-Type: application/json
  {"role": "executive"}   # أي دور من جدول §3

  → 200 {"access_token": "eyJ...", "token_type": "bearer", "principal": {...}}
  ```

- **الإنتاج (OIDC)**: سجّل الدخول عبر مزوّد الهوية المؤسسي.

استدعاءات API: `Authorization: Bearer <token>` (§6). فحوصات الصحة:
`GET /healthz`, `GET /readyz`.

## 3. المستخدمون والأدوار والصلاحيات

### 3.1 الأدوار (خطة §13.1)

| الدور | القدرات الرئيسية |
|---|---|
| **Executive** | لوحات تحكم، عرض المؤسسة، اسأل EIL، عرض النتائج |
| **Portfolio Manager** | إنشاء/تحرير المشاريع، إدارة التخصيصات/السيناريوهات، نشر السيناريوهات، تحرير نموذج الترتيب |
| **Project Manager** | إنشاء/تحرير المشاريع والمهام، تقديم الطلبات، قبول اقتراحات الذكاء الاصطناعي (مجاله) |
| **Dept Head** | عرض المؤسسة، مراجعة اقتراحات الذكاء الاصطناعي، نشر السيناريوهات (وحدته) |
| **Resource Manager** | إدارة التخصيصات/السيناريوهات، نشر السيناريوهات، إدارة الموارد |
| **Team Member** | عرض، مراجعة اقتراحات الذكاء الاصطناعي (وحدته) |
| **PMO Analyst** | لوحات تحكم، تحرير نموذج الترتيب، مراجعة اقتراحات الذكاء الاصطناعي |
| **AI Reviewer** | مراجعة اقتراحات الذكاء الاصطناعي |
| **Auditor** | عرض سجل المراجعات (للقراءة فقط) |
| **Admin** | كل شيء (نطاق المؤسسة) |
| **Integration Admin** | إدارة الموصلات والمصادر، موافقة التغييرات على السجل الموزع |

### 3.2 نموذج الصلاحيات

- **رفض افتراضي**: كل نقطة نهاية تتطلب صلاحية.
- الصلاحيات هي بيانات مزروعة (`eil/modules/seed_data.py`) — مصفوفة §13.1، يمكن تغييرها دون تعديل برمجي.
- **نطاق ABAC**: بعض الأدوار محدودة لوحدة العمل الخاصة بهم (مثل project_manager).
- **قواعد SoD** (خطة §13.2، تُرجع `403 sod_violation` ويتم تسجيلها):
  - **SOD-1** — لا يمكنك موافقة طلب أو طلب تغيير تم إنشاؤه أو تقديمه بنفسك.
  - **SOD-2** — مُصادق التجاوز على الأولوية يجب أن يختلف عن المطلوب.
  - **SOD-3** — من عدّل نموذج الترتيب النشط يتجنب موافقة التجاوزات على دورة نفسها.
  - **SOD-4** — تغييرات سجل المصادر الموصوفة أو علامات معالجة الذكاء الاصطناعي
    تتطلب شخصين مختلفين (مطلوب ≠ مصادق).
  - **SOD-5** — دور Auditor للقراءة فقط ولا يجمع مع أي دور كتابة.
  - **SOD-6** — نشر السيناريو يتطلب موافقة شخص آخر عن المؤلف.
- كل رفض يُسجَّل في سجل المراجعات.

## 4. المفاهيم الأساسية

### 4.1 عناصر العمل

كل شيء في المنصة هو `WorkItem` بنوع وحالة. الأنواع: objective، key_result،
demand، program، project، task، milestone، commitment، risk، issue، benefit،
decision. الحالات: draft، submitted، approved، rejected، active، on_hold،
completed، cancelled.

### 4.2 الرسم البياني للعمل (Enterprise Work Graph)

العناصر مربوطة بحواف مكتوبة بنوعين. قواعد الربط هي بيانات (`link_type_rule`،
خطة §7.2):
- `part_of` — عنصر جزء من عنصر آخر.
- `aligns_to` — محاذاة أهداف/نتائج رئيسية.
- `fulfils` — الالتزام ← برنامج/مبادرة.
- `realizes` — الفائدة → أهداف/مشاريع/برامج.
- `mitigates` — مخاطر/مشاكل ← مهام/مشاريع.
- `depends_on` — تبعيات (إكمالية الدورات مرفوضة لـ depends_on).
- `duplicate_of` — روابط التكرار.

عمليات الرسم البياني: الجيران، التسلسل الجذري (lineage)، المسار،
التأثير اللاحق (`GET /graph/nodes/{id}/downstream-impact`)، بالإضافة إلى
تقرير السلامة (`GET /graph/integrity`).

### 4.3 النتائج الاستراتيجية

- **الأهداف (OKRs)**: قمة التسلسل.
- **النتائج الرئيسية**: نتائج رئيسية تحت الأهداف.
- **الطلبات**: طلبات عمل شركية؛ عند الموافقة → **تحويل تلقائي** إلى
  برنامج/مشروع من قالب التسليم (WBS، مزامن، بوابات، فوائد) مع إبقاء روابط
  المحاذاة والدرجات.
- **الفوائد**: النتائج الاستراتيجية المُنجزة بواسطة الأهداف (رؤية تجميع
  §5.11).
- **الالتزامات**: الوعود بالتسليم مع تواريخ مستحقة وثقة تسليم (مونتي كارلو).

### 4.4 التخصيص والقدرة (Scenario 3)

- **التخصيصات**: ساعات مخططة لكل موارد لكل نافذة زمنية. إنشاء على صفحة
  القدرة (النموذج: المورد، عنصر العمل اختياري، تاريخ البداية/النهاية، الساعات
  في الأسبوع). Backend: `GET/POST /allocations`،
  `PATCH /allocations/{id}` (دور admin).
- **خريطة الحرارة**: الاستخدام الأسبوعي لكل موارد — أخضر/عنبر/أحمر حسب
  `capacity_amber_pct` (85) / `capacity_red_pct` (100).
- **الازدحامات**: الحمل الزائد مع عناصر الالتزامات/المشاريع/الأهداف المتأثرة
  (تأثير لاحق في الرسم البياني مع وزن الانتقاد).

### 4.5 المزامنة (أنظمة السجلات المصدر)

- **المصادر الموصوفة** (admin): تسجيل الأنظمة الخارجية (`type` ∈ p6, eam,
  erp, hr, m365).
- **Sync now**: `POST /integrations/sources/{id}/sync` — تشغيل جذب فوري؛
  عبور Beat كل 60 ثانية عند غياب Redis.
- **الصحة + التأخر**: `GET /integrations/sources/{id}/status` — حالة الصحة،
  وقت المزامنة الأخير، التأخر، عدد الأخطاء، النزاعات غير المحلولة.
- **النزاعات**: التغييرات الخارجية على الحقول غير المملوكة —
  قائمة (`GET .../conflicts`)، حل (`POST .../resolve`).
- **الكتابات**: كتابات مرجعية موجهة بصلاحية موجهة (مقرر/منفذ؛ مفعّل بشكل
  افتراضي لا).
- **علامات معالجة الذكاء الاصطناعي**: موجهة بقاعدة SOD-4.

## 5. استعراض الميزات

### 5.1 لوحة التنفيذ (Dashboard — النظرة التنفيذية) — `/` (كل الأدوار)

إجمالي الالتزامات، متوسط الثقة في التسليم حسب وحدة، الحالة الدرجية (RAG)،
العناصر المتأخرة والقادمة، الموافقات المعلقة، العناصر في الخطر.

### 5.2 الأهداف والنتائج الرئيسية (Objectives & OKRs) — `/objectives`

قائمة الأهداف ونتائجها الرئيسية. افتح بهدفًا لرؤية: نتائجه الرئيسية،
الطلبات التابعة له، تأثيرها اللاحق في الرسم البياني، وتجميع الفوائد (§5.11).

### 5.3 خط طلبات الشركة — `/demand`

قائمة الطلبات؛ تقديم طلب جديد (العنوان، الوصف، الأولوية، محاذاة الطلب مع
الأهداف)؛ الموافقون يتلقونه على صفحة **الموافقات**.

### 5.4 الموافقات — `/approvals`

بريد الموافقات المعلقة: الموافقة، الرفض (بسبب)، التفويض/التصعيد حسب
سير العمل الحوكمي. الموافقات محدودة بمدة (`approval.due_at`).

### 5.5 سجل المراجعات — `/audit`

سجل مراجعات متسلسل بالحلقة الشعابية (hash chain) وإضافات فقط — كل فعل
مميز. تصدير وفلترة (التصدير يتحقق من سلسلة الحلقات؛ رؤية
`eil/modules/audit/service.py`).

### 5.6 الرسم البياني للعمل — `/graph` (كل الأدوار)

لوحة React Flow: اختر جذرًا ("Select a root item")؛ **الجيران**،
**التسلسل الجذري** (حلقات part_of/aligns_to)، **التأثير اللاحق** (العناصر
المتأثرة مع وزن الانتقاد). فلاتر حسب نوع الرابط؛ ألوان حسب RAG/ثقة الثقة؛
توسيع/طي.

### 5.7 لوحة الترتيب/الأولويات — `/prioritization` (portfolio_manager, admin)

- كل عنصر: الترتيب (rank)، النوع، المستوى (1–4)، الدرجة، أسباب التسجيل
  (rationale)، شارة خط القطع (cut-line).
- **الدرجة**: `score = 100 × Σ wᵢ·nᵢ` على مقاييس مسمّاة (anchored scales)
  لكل معيار + أوزان؛ مقاييس المستويات؛ قواعد التحديد (HSE/regulatory).
- **نموذج التجاوز**: ارفع المستوى مع توجيه + مصادق مختلف — إرساله كأنك
  تطلب من نفسك تمنحك `403 sod_violation` (SoD-2)؛ كل تجاوز يُسجل
  (`priority.overridden`).
- موافقة الطلب على `/demand` → المشروع يُنشأ تلقائيًا من قالب التسليم
  مع الروابط والدرجات.

### 5.8 القدرة والسيناريوهات (Scenario 3) — `/capacity` (resource_manager, portfolio_manager, admin)

- **خريطة الحرارة**: حسب الموارد × الأسبوع للاستخدام مع تلميح (demand،
  available، utilisation).
- **التخصيصات** (جديدة): نموذج تخصيص على هذه الصفحة؛ قائمة + تحرير ساعات
  الأسبوع لكل تخصيص.
- **الازدحامات**: تأثير الازدحام — الالتزامات/المشاريع/الأهداف
  المتأثرة، مع الانتقاد.
- **المُحسّن**: أربع استراتيجيات (reassign / resequence / reprioritise /
  augment) مع دلتات مكمّمة (ساعات غير مغطاة/محمّلة).
- **سيناريوهات/what-if**: إنشاء سيناريوهات، ضبط التخصيصات، مقارنة دلتات
  المقاييس مع الخط الأساسي، نشر عبر موافقة (SoD-6).

### 5.9 المخاطر والتصعيد — `/risk` (كل الأدوار)

- **رادار المخاطر**: عناصر في الخطر مع ثقة التسليم × التأثير، ملونة حسب
  درجة المخاطرة؛ مرتبة حسب درجة المخاطرة.
- **بريد التصعيد**: تصعيدات مفتوحة مع تواريخ استحقاق؛ إعلان التلقي
  (`PATCH /api/v1/escalations/{id}/acknowledge`).

### 5.10 الرؤية التنفيذية — `/executive` (executive)

ستة أقسام:
1. **الملتزم به** — الالتزامات حسب الوحدة التنظيمية + المتوسط.
2. **الأكثر أهمية** — أهم الأولويات مع الدرجة والأعلام (override).
3. **موارد محدودة** — قيود القدرة (مورد، أسبوع، حالة).
4. **في خطر ولماذا** — رادار المخاطر + العوامل.
5. **النتائج الاستراتيجية المتأثرة** — أهداف بالثقة + عدد الفوائد
   (التجميع، §5.11).
6. **تحتاج تدخل** — التصعيدات المفتوحة + القرارات الموصى بها.

### 5.11 تجميع الفوائد (Strategic outcomes — benefits)

`GET /api/v1/items/benefit-rollup` — لكل هدف نشط: عدد الفوائد، عدد
النتائج الرئيسية، مجموع الفعلي/الهدف/التوقع، آخر تاريخ فعلي، حالة
المتابعة. يُعرض على الصفحة التنفيذية كلوحة **"النتائج الاستراتيجية — تجميع
الفوائد"**.

### 5.12 وضع العرض — `/executive/presenter`

رؤية تنفيذية بملء الشاشة:
- **محدد الكم** — مرر الخط الزمني لإعادة عرض الرؤية كما في أي تاريخ (replay).
- **التحديث التلقائي** (Auto-refresh).

### 5.13 اسأل EIL — `/assistant` (أدوار مع صلاحية `ai.assistant`)

اكتب سؤالًا؛ يُجيب EIL باستخدام الأدوات للقراءة فقط
(`query_graph`, `get_capacity`, `list_commitments`, `get_risks`,
`explain_confidence`, `get_priorities`) ويعرض معرفات العناصر من النتائج
كمصادر استشهاد. عند تعطيل الذكاء الاصطناعي (الوضع المحلي: `AI_ENABLED=false`)
تظهر الحالة المرحبة والنقطة الفارغة؛ الواجهة البرمجية تعيد `409
not_available`. السجل: `GET /api/v1/assistant/conversations`.

### 5.14 صندوق الذكاء الاصطناعي (AI Inbox) — `/ai/inbox` (أدوار مراجعة/قبول)

مراجعة اقتراحات الذكاء الاصطناعي من استخراج محادثات/بريد إلكتروني:
- **قبول** — ترقية لعنصر مهمة/التزام مع الارتباط الأصلي (`derived_from`).
- **قبول بالتعديل** — تعديل البيانات ثم قبول.
- **رفض** مع سبب (يُخزن كإشارة راجعة).
- **رفض مجمّع** للعناصر المحددة.
- **لوحة التكرار** — ربط العناصر المكررة (`duplicate_of`).

### 5.15 الإدارة — الموصلات — `/admin/connectors` (integration_admin, admin)

- **جدول الموصلات**: النظام، أنواع السجلات، الأنماط، دعم الإرسال.
- **المصادر**: إنشاء (`type`، `name`، `owner` مطلوب)، تفعيل/تعطيل،
  **حذف عند التعطيل**، **Sync now** (`POST /integrations/sources/{id}/sync`)،
  **معالجة الذكاء الاصطناعي** (قاعدة SOD-4 — يتطلب مُصادقًا ثانيًا عند
  التفعيل).
- **النزاعات**: تغييرات حقول غير مملوكة — حل.
- **الكتابات**: موافقة/تنفيذ عمليات الكتابة الموجهة.

## 6. ملخص الواجهة البرمجية (النقاط الرئيسية)

جميع استدعاءات: `Authorization: Bearer <token>`; بادئة API `/api/v1`.

| المنطقة | نقاط النهاية (الدور) |
|---|---|

## 7. تصحيح المشكلات الشائعة

### 7.1 403 Forbidden — لماذا

نقطة النهاية تتطلب صلاحية يملكها دورك أو لا (رفض افتراضي).
مثال: `GET/POST /integrations/sources` → `connector.manage` — ملك لـ
**integration_admin** و**admin** فقط. سجّل الدخول بأحد هذين الأدوارين:

```
POST /api/v1/auth/dev-login  {"role": "integration_admin"}
```

### 7.2 422 Unprocessable Entity عند إنشاء مصدر

يتحقق `POST /integrations/sources` من `type`، `name` و`owner` — فعل الرجاء
تعبئة **name** و**owner** (زر الإنشاء يُعطل عندما يكونا فارغين)؛ `type`
يجب أن يكون أحد أنظمة الموصلات المدمجة (p6, eam, erp, hr, m365).

### 7.3 مشاكل ترحيل قواعد البيانات (مُصلح)

قواعد البيانات الحالية كانت تحتوي دقائق على دفع بسيط (وجود التوقيتات على
جدول الدرجات) — تم إصلاحها بالترحيلات
`0008_add_missing_ts` + `0009_drop_score_version`، واختبار
يقوم بذلك تلقائيًا على قاعدة عيانة (`tests/test_migration_drift.py`).

### 7.4 التصميم البلدي والاستضافة

- لا يتم تنفيذ اختبارات Playwright في هذا البيئة (ازدحام برنامج ثقيل يمنع
  تحميل عناصر الاختبار).
- الوضع المحلي: SQLite + JWT تطويري.

### 7.5 ملاحظات أمنية

- ترويسة CSP + ترويسات أمنية على كل استجابات API (Phase 9, T9.2).
- تحديد أجهزة/مستخدمين (rate limiting) حسب الطابع + حسب المستخدم.
- قوائم CORS والمضيفات الموثوقة — خارج الوضع المحلي/العرضي، يجب تعيين
  `CORS_ORIGINS` و`TRUSTED_HOSTS`.
- حماية SSRF لروابط الموصلات (`connectors/sdk/urls.py`).
- `make security-scan` — مسح الأنماط السرية + مراجعة التبعيات.
- قائمة التحقق من ASVS L2: `docs/asvs-l2-checklist.md`.
